\begin{honesty}[Two prior inaccuracies about this Zenodo archival, found while writing this revision]
First, an earlier draft of this section cited \texttt{v31}
identifiers that were Git tags with no corresponding GitHub Release
object, so Zenodo's GitHub integration --- which archives
\emph{releases}, not bare tags --- had not minted a version DOI for
either repository. That is fixed above: both \texttt{v31} identifiers
are now published GitHub Releases with their own version DOIs.
Second, every earlier draft of this paper, going back to the first
v30 draft, stated that \texttt{beal-conjecture} and
\texttt{beal-level-26-foundations} share one concept DOI,
\texttt{10.5281/zenodo.22379293}. Checking the public Zenodo API
while writing this revision shows that is false:
\texttt{beal-conjecture}'s own releases, including \texttt{22863527}
(v30) and \texttt{22884682} (v31) above, are archived under the
separate concept \texttt{10.5281/zenodo.22041831}, and
\texttt{10.5281/zenodo.22379293} is exclusively
\texttt{beal-level-26-foundations}'s concept. This paper now cites
the correct concept DOI for each repository.
\end{honesty}

\paragraph{Sage and JSON.}
The Lean displays are paired with static Sage scripts and JSON pins,
not with a Sage kernel in CI (\texttt{sage\_ran: false} in every
certificate below):
\texttt{sagemath/tate\_nero\_29.sage};
\texttt{sagemath/ribet\_no\_newforms\_32.sage} with
\texttt{certs/ribet\_no\_newforms\_32.json}
(\texttt{full=1}, \texttt{new=1}, \texttt{level16=0},
\texttt{sturm=8});
\texttt{sagemath/kolyvagin\_rank0\_26.sage} with
\texttt{certs/kolyvagin\_rank0\_26.json} and
\texttt{sagemath/kolyvagin\_fintype\_subsingleton.sage} with
\texttt{certs/kolyvagin\_fintype\_subsingleton.json}.
LMFDB labels used as pins are \texttt{32a1}, \texttt{26a1}, and
\texttt{26b1}~\cite{lmfdb}. Lean verifies arithmetic involving the
values these certificates carry; it does not verify their
provenance, since no Sage kernel runs in CI.

\begin{honesty}[Certificate schema predates the v31 rename]
The two Kolyvagin JSON certificates above are immutable per-version
snapshots, tagged \texttt{kolyvagin-rank0-final-v29} and
\texttt{kolyvagin-fintype-subsingleton-v28} in their own
\texttt{version} field. Their field names
\texttt{IsRankZero\_is\_Subsingleton}, \texttt{IsRankZero\_on\_26a1},
and \texttt{IsRankZero\_on\_26b1} predate the Lean-side rename of
\texttt{IsRankZero} to \texttt{IsSubsingleton} described in
Section~\ref{sec:kolyvagin}; a \texttt{schema\_note} field added to
each certificate at v31 states this explicitly. The boolean values
are unaffected by the rename, since \texttt{Subsingleton} itself did
not change --- only its Lean-side name did.
\end{honesty}
