# LEVEL-26 REPRODUCIBLE CERTIFICATE AND EXACT TRUST BOUNDARY

## Reproduction

The external replay command is:

    sage sagemath/reproduce_level26_descent.sage \
      | tee sagemath/sage_mwrank_level26.log

The script prints the exact Sage version, Sage root, mwrank version probe,
database label, returned a-invariants, conductor, discriminant, torsion order,
proved rank, and `two_descent(second_limit=12)` result before any interpretation.

The dependency-free p-adic certificate is regenerated and checked with:

    python3 scripts/level26_descent_certificate.py
    python3 scripts/level26_descent_certificate.py --check

Its immutable outputs are
`certificates/level26_descent_certificate.json` and the human-readable
`sagemath/certs_26a1_26b1.log`.  The producer covers every
combination of:

* both coefficient-defined Lean curves;
* all eight signed S-unit representatives;
* all four-plus-six archived quartic rows; and
* moduli `2^6` and `13^2`.

For each combination it records `(x,z,y)` with `(x,z)` primitive modulo the
prime, selects one coordinate `u`, and checks

    v_p(F(x,z,y)) > 2 v_p(∂F/∂u(x,z,y)),

where

    F = d*y^2-(a*x^4+b*x^3*z+c*x^2*z^2+d4*x*z^3+e*z^4).

The strong one-variable Hensel lemma therefore gives a root in `Z_p` while
the other two coordinates remain fixed.  All 160 entries are lift
certificates; no local obstruction is inferred from a bounded failed search.

Lean repeats their reductions modulo `2` and `13` in
`all_twisted_congruence_witnesses_checked`; both computations depend on the
S-unit, unlike the superseded 80-check audit.  The p-adic conclusion itself is
accepted only through `GenuinePAdicCertificate_26`, whose fields are actual
`Q_2`/`Q_13` points and cannot be inhabited by JSON text or a Boolean.

## Model identification

The archived coefficient-defined Lean models are:

* `lean_E26a1 = [1,-1,1,-3,3]`;
* `lean_E26b1 = [1,0,1,-5,-8]`.

These names are repository identifiers.  They are not asserted to be the
current LMFDB curves returned by the strings `26a1` and `26b1`.  The Sage
producer prints the database-returned coefficients so a future run cannot
silently conflate the two naming systems.  The quartic rows remain attached to
the coefficient-defined Lean models exactly as checked in Lean and JSON.

## Exact boundary

The JSON checker proves the displayed Hensel hypotheses for every listed
covering. It does not prove:

* that the archived quartics exhaust the relevant coverings;
* that the resulting classes are the full 2-Selmer group; or
* the Selmer-to-Mordell-Weil rank theorem.

The normalized zero mwrank fields retained in Lean are historical external
report fields, not outputs regenerated by the Python producer.  A fresh Sage
run belongs in `sagemath/sage_mwrank_level26.log`, which cannot overwrite the
checked congruence log.

`GenuinePAdicCertificate_26` is the proof-relevant Lean interface for the
local points. `Level26ExternalComputationInterface` is the narrower remaining
interface connecting those points and the externally reported zero fields to
`CompleteTwoDescent`. No `decide` theorem, transcript Boolean, or prose claim
inhabits either interface.
